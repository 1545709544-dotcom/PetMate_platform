# 04 · 技术架构说明

> 面向技术对接方、合作伙伴与开发团队,介绍 PetMate 的系统构成、运行方式与对接规范。

---

## 一、系统总览

PetMate 是一个典型的"前后端分离"Web 应用,由三大子系统组成:

| 子系统 | 形态 | 角色 |
| :--- | :--- | :--- |
| **用户端 Web** | 响应式 Web 页面(桌面/平板/手机) | 普通宠物主 |
| **商家工作台** | PC 端 Web 应用 | 宠物门店、医院、寄养家庭、技师 |
| **平台管理后台** | 仅 PC 端 Web 应用 | 平台运营/客服/财务/超管 |

三个子系统共享同一套后端 API 服务与数据库,根据角色看到不同的界面与可执行操作。

## 二、技术栈

| 层 | 选型 |
| :--- | :--- |
| 前端 | Vue 3.5 + TypeScript 5.6 + Vite 5 + Element Plus 2 + Pinia + Vue Router 4 + Axios + ECharts |
| 后端 | Spring Boot 3.3 + JDK 21 LTS + Spring JDBC + JWT (jjwt) + BCrypt |
| 数据库 | MySQL 8.0 (utf8mb4) |
| 构建 | Maven Wrapper(后端)/ Vite(前端) |
| 适配 | postcss-px-to-viewport,设计稿 1920px,输出 vw 单位 |
| 部署 | 单机/容器均可,生产推荐 Docker Compose |

## 四、后端模块构成

后端代码位于 `petmate-backend/src/main/java/com/petmate/`,按业务域拆分为多个子模块:

| 模块 | 职责 |
| :--- | :--- |
| `auth` | 登录、注册、令牌签发 |
| `user` | 用户资料、地址、收藏、优惠券 |
| `pet` | 宠物档案、健康记录、成长日记 |
| `product` | 商品分类、商品详情、搜索、推荐 |
| `order` | 购物车、订单、状态机 |
| `pay` | 支付接入(微信/支付宝)与支付日志 |
| `refund` | 退款售后 |
| `seckill` | 限时秒杀(库存原子扣减) |
| `points` | 积分体系 |
| `adoption` | 领养救助 |
| `community` | 社区动态、互动、内容审核、敏感词 |
| `consult` | AI 智能问诊(基于关键词的 mock,可替换为真实 LLM) |
| `appointment` | 美容/寄养/训练的预约 |
| `service` | 服务管理 |
| `track` | 用户行为埋点(用于推荐系统) |
| `merchant` | 商家后台接口 |
| `admin` | 平台管理后台接口 |
| `security` | JWT 鉴权过滤器、令牌上下文、幂等性服务 |
| `common` | 统一响应、错误码、异常、链路追踪 |
| `config` | Web 配置(CORS 等) |

## 五、前端模块构成

前端代码位于 `frontend/web/src/`,按业务域组织:

| 目录 | 内容 |
| :--- | :--- |
| `views/user/` | 用户端页面:首页、商品、社区、问诊、订单、宠物、个人中心、领养等 |
| `views/merchant/` | 商家工作台:工作台、商品、订单、服务、客户、退款、财务、数据看板 |
| `views/admin/` | 管理后台:仪表盘、用户、商家、商品、订单、内容审核、营销、风控、权限 |
| `api/modules/` | 按业务域组织的接口调用模块(auth、product、order、community 等) |
| `router/` | 路由配置,含登录态与角色守卫 |
| `stores/` | Pinia 全局状态管理 |
| `components/` | 公共组件 |
| `composables/` | 可复用组合式函数 |
| `layouts/` | 页面布局 |
| `utils/` | 工具函数(请求封装、埋点等) |

页面总数 60+,覆盖普通用户、商家、管理员三类角色的全部日常操作。

## 六、数据库设计

## 七、API 设计

### 7.1 基本约定

- 所有接口前缀 `/api/v1`
- 请求/响应均使用 JSON,字符集 UTF-8
- 鉴权:除登录/注册外,均需在请求头携带 `Authorization: Bearer <token>`
- 角色标识:`X-Role: USER/MERCHANT/ADMIN`
- 商家子账号:`X-Store-Id: {merchant_id}`

### 7.2 统一响应格式

```json
{
  "code": 0,
  "msg": "ok",
  "data": { ... },
  "traceId": "abc123"
}
```

### 7.3 错误码段

| 错误码段 | 含义 |
| :--- | :--- |
| 0 | 成功 |
| 10001 | 参数错误 |
| 20001 | 未登录 |
| 30001 | 库存不足 |
| 40001 | 订单不存在 |
| 50001 | 余额不足 |
| 60001 | 敏感词命中 |
| 70001 | AI 服务繁忙 |
| 90001 | 无权限 |

### 7.4 接口总览(按域)

| 业务域 | 关键端点 |
| :--- | :--- |
| 认证 | `POST /auth/login`、`GET /auth/me` |

| 社区 | `/community/post`、`/community/post/:id`、`/community/feed` |

## 八、核心业务流程

### 8.1 下单支付流程

```
用户加购 → 购物车 → 结算页(选地址/券/支付方式)
        → 提交订单(扣库存、计算金额)
        → 跳转支付(微信/支付宝/余额)
        → 支付回调 → 订单状态更新
        → 商家发货 → 物流跟踪
        → 用户确认/超时自动收货
        → 订单完成
```

### 8.2 AI 问诊流程

```
用户发起问诊 → 创建问诊会话
            → 用户多轮输入(文字/语音/图片)
            → 问诊服务综合判断
            → 输出分级建议 + 关联商品
            → 会话记录存入历史
```

### 8.3 推荐系统流程

```
用户行为埋点(浏览/收藏/加购/购买)
        → 行为日志入库
        → 离线/在线计算用户画像
        → 召回候选集(协同过滤 + 内容)
        → 排序后下发首页 feed
```

## 九、运行与部署

### 9.1 准备环境

| 依赖 | 最低版本 | 验证命令 |
| :--- | :--- | :--- |
| JDK | 21 LTS | `java -version` |
| Maven | 3.9+(项目已带 wrapper) | `mvn -version` |
| Node.js | 20+ | `node -v` |
| MySQL | 8.0 | `mysql --version` |

### 9.2 启动顺序

1. 初始化数据库:`cd petmate-backend/sql && ./reset_and_seed.sh`
2. 启动后端:`cd petmate-backend && mvnw spring-boot:run`,监听 `8080`
3. 启动前端:`cd frontend/web && npm install && npm run dev`,访问 `http://localhost:5173`

> 前端已配置代理,`/api/*` 自动转发到 `http://localhost:8080`。

### 9.3 生产环境检查清单

- 修改 `petmate.jwt.secret` 为强随机串(≥ 32 字节)
- MySQL 使用专用账号,最小权限
- 引入 Redis 替代内存版幂等锁
- 接入真实 LLM(智谱 GLM-4 / 通义千问 / OpenAI 等)
- 接入真实支付通道
- 启用 HTTPS、配置 CORS 白名单
- 引入完整日志(ELK / Loki)与监控(Prometheus + Grafana)
- Docker Compose 编排 MySQL / Redis / Backend / Frontend / Nginx

## 十、安全设计

- **传输安全**:全站 HTTPS,关键接口要求登录态
- **认证**:JWT 无状态令牌,BCrypt 加密存储用户密码
- **授权**:基于角色(RBAC)+ 接口级注解
- **防滥用**:关键写操作(支付、下单)采用幂等键防重放
- **内容安全**:社区内容 AI 初审 + 敏感词库 + 人工抽审
- **数据隔离**:商家只能看自己门店的数据,普通用户只能看自己订单

## 十一、扩展方向

PetMate 当前实现已覆盖完整业务流程,以下方向可在后续版本中持续增强:

- 真实 LLM 接入(替换 mock)
- 移动端原生应用(基于现有响应式 Web 的渐进增强)
- 更多支付与营销玩法(预付卡、跨店满减)
- 国际化(多语言、多币种)
- 物联网接入(智能喂食器、智能猫砂盆的数据回流)
- 区块链存证(领养协议、防伪溯源)
