## 二、素材来源与处理

### 原型部分（26 个）

来源：`UI/stitch/` 下 26 组 Google Stitch 导出资产，每组含 `code.html`（可交互原型）+ `screen.png`（设计稿）。

处理方式：图片压缩为 JPEG 内嵌，原型 HTML 以 base64 编码内嵌后通过 iframe `srcdoc` 渲染 —— 这样单文件即可离线浏览设计稿，联网时还能直接点击原型。

### 真实系统截图（38 张）

处理方式：拉起完整三层服务（MySQL 3306 → Spring Boot 8080 → Vite 5173），用浏览器自动化按三个角色分别登录，逐页截取首屏。

**过程中发现并修复的一个问题**：演示账号 `13800138000` 未实名（`t_user.verified = 0`），导致 `/adoption/publish`、`/seckill`、`/user/footprint`、`/aftersale` 四个页面被实名门禁拦截重定向。已补齐该账号的实名信息后重截，38 张全部正常。

### 原型 ↔ 真实页面的映射关系

**关键发现**：`frontend/web/src/router/routes.ts` 里每个路由都带 `meta.source` 字段，标注了它来自哪个原型 HTML。这是现成的映射表，因此「原型 → 落地页面」的对应关系是**从代码里解析出来的，不是人工猜测**。

解析脚本：`_verify_docx/parse_routes.py` → 输出 28 条映射 + 102 条完整路由。

## 四、几个刻意的取舍

**用真实数据，不用文档里的旧数字。** 产品说明书里写的是「27 张表 / 60+ 页面」，实测数据库是 64 张表、前端 101 个页面、33 个 Controller。作品集里全部改为实测值。

**技术边界如实写。** 明确写明框架底层不是强项、编码借助 AI 工具完成，把重点放在「能讲清业务设计 + 能演示 + 能回答追问」。这比硬撑「精通」在面试里安全得多。

**已知限制主动列出。** 支付为演示态、积分上限并发非原子、权限体系为演示态、未做压测——都写在作品集里。面试官问到不会措手不及，还显得可信。

**准备了两套演示方案。** 真实系统演示 + 单文件离线兜底，避免现场网络或环境出问题。

## 五、使用建议

### 面试前

- 通读 `PetMate-作品集.html` 的「面试问答」章节，把 6 个问题的答案念一遍，念不顺的地方就是没想清楚的地方
- 重点准备「你具体做了哪部分」和「最难的问题是什么」两题

### 现场演示

- 按第 5 章的 8 分钟动线走，不要随机点页面
- 三个浏览器窗口提前登录好三个账号
- 检查购物车、订单、健康档案里都有数据，别演示空列表

### 发送给 HR / 面试官

- 直接发 `PetMate-作品集.html` 单文件即可，对方双击就能看，无需部署
- 如需在 GitHub 展示，用 `PetMate-作品集.md` 配合 `assets/demo/` 目录

## 六、复用方式

素材更新后重新生成：


## 七、PDF 版的排版要点

PDF 不是网页直接打印出来的，而是一份**专门的 A4 打印模板**（`portfolio_print_tpl.html`），针对求职场景做了这些处理：

- **分页可控**：内容按页手动分组，每页高度都控制在 A4 可用区内，不会出现卡片被拦腰切断
- **封面 / 目录 / 页码**：29 页结构，封面和封底不编页码，正文编号 1–27
- **图片按卡片裁切**：原型与截图统一 2 列、等高展示页面顶部区域，排版整齐
- **字体已嵌入**：微软雅黑子集随文件打包，换任何设备打开都不会乱码
- **色彩保真**：开启 `print-color-adjust: exact`，品牌橙与浅色底在 PDF 里不丢失
- **尺寸精确**：实测 209.9 × 297.0 mm，A4 纵向，页边距 15/13/16 mm

**页数结构（29 页）**：封面 1 · 目录 1 · 项目定位 1 · 我的角色 1 · 原型 5 · 真实截图 7 · 演示脚本 3 · 功能亮点 2 · 技术架构与安全 3 · 工程质量 2 · 面试问答 2 · 封底 1

渲染时会自动检查每页高度是否超出 A4 可用高度（1005px @96dpi）并打印告警，改完模板重跑 `render-pdf.mjs` 即可确认。
